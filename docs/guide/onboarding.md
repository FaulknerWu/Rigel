# 开发环境搭建与项目启动指南

本文档旨在指导新加入项目的研发人员快速了解代码库的基本结构，并完成本地运行环境的配置与核心服务的构建。

---

## 1. 核心目录结构

本系统的顶层目录包含三个功能独立的区块，了解它们的定位有助于规范后续的开发工作：

*   **`core/`**：系统的源代码目录，使用 Rust 语言编写，涵盖主程序及模块实现，是日常开发的重心区域。
*   **`docs/`**：项目的综合文档库，当前包含 ADR、设计规范与开发导读。
*   **`labs/`**：内部技术预研与实验专区，当前主要保存 Python 侧依赖声明与锁文件，请谨慎基于此目录进行生产级别的开发。

## 2. 工具链与运行环境准备

当前仓库可验证的运行前提主要包括 Rust 工具链与可选的 FalkorDB 开发环境。需要注意：仓库中尚未实现真正依赖 FalkorDB 的业务流程，但技术选型已经固定在 ADR 中。

### 阶段一：安装并配置 Rust 工具链

系统核心程序由 Rust 开发。如需在本地安装，请执行以下官方提供的初始化命令：

```bash
# macOS 或基于 Linux 的系统环境
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```
*提示：当前 `core/rust-toolchain.toml` 仅声明 `stable` 通道，未额外锁定具体版本。*

### 阶段二：部署 FalkorDB 数据库

Rigel 的目标架构采用 FalkorDB 作为主图存储。虽然当前代码尚未接入实际写入逻辑，但如果你准备继续补齐图存储能力，可以先在本地启动数据库：

```bash
docker run -p 6379:6379 -it --rm falkordb/falkordb:latest
```
当前仅执行仓库内已有的构建、测试与 CLI 冒烟时，不要求该容器必须运行。

---

## 3. 本地构建与验证测试

在配置好上述前置条件后，请按如下流程编译并检验本地开发环境。

1. **进入开发级目录工作区**：
```bash
cd core
```

2. **拉取依赖与构建可执行文件**：
首次执行构建过程会涉及 Tree-sitter 等底层组件的获取及编译，可能需要一些时间，请耐心等待完成。
```bash
cargo build
```

3. **执行冒烟测试及单元测试（建议）**：
当前测试主要用于验证 crate 骨架和依赖链路可用。
```bash
cargo test
```

4. **调起系统核心入口并核实 CLI 状态**：
当前 CLI 仅包含基础入口与帮助信息，用于验证运行链路接通。
```bash
cargo run -- --help
```
*(当前 `main.rs` 仅完成最小 CLI 脚手架，尚未提供索引、抽取、检索等子命令。)*
