# EXP-001: Java AST 与语义解析可行性实验

## 1. 背景

Rigel 的索引主链路调整为两阶段：先由 AST 构建结构骨架，再由语言服务（LSP）补充跨文件语义边。前者负责稳定、确定性的结构抽取，后者负责需要符号解析才能确认的语义关系。如果 Java AST 方案在实体识别、源码定位、错误恢复或增量重解析上存在明显缺口，或者 LSP 在跨文件符号解析、错误恢复、性能与可用性上不稳定，那么后续的存储模型、索引流程与关系构建都会建立在不稳定前提上。

## 2. 实验目标

本实验需要回答以下问题：

1. 当前选定的 Java AST 解析方案，是否能稳定解析 Rigel 首期所需的 Java 源码样本。
2. 是否能从语法树中稳定抽取文件、类型、可调用实体三类基础实体，并构建 `defines` 结构骨架。
3. 是否能拿到实体抽取与关系构建所需的关键元信息，并稳定生成设计文档要求的核心字段，包括 `entity_kind`、`name`、`file_path`、`start_line`、`end_line` 以及关系起止实体定位信息。
4. 当源码存在语法错误或不完整片段时，AST 解析是否仍能返回可用的部分结构，而不是整文件报废。
5. 当前选定的 Java LSP 方案，是否能为代表性的跨文件引用稳定返回定义位置，并支撑 `calls`、`extends`、`implements`、`imports` 等语义边补全。
